# Assignment 01 — What happens between typing a URL and seeing the page?

When I type a URL such as `https://www.example.com/index.html` into the browser and press Enter, the browser first splits it into the scheme (`https`), the host (`www.example.com`) and the path, and checks its caches for a saved copy. If the server's IP address is not cached, the browser asks a DNS resolver, which walks through the root, top-level-domain and authoritative name servers to translate the domain name into an IP address. The browser then opens a TCP connection to that address (the three-way handshake) and, because the scheme is HTTPS, performs a TLS handshake to verify the server's certificate and agree on encryption keys. Over this secure channel it sends an HTTP `GET` request; the server (often behind a load balancer or CDN) processes it and returns an HTTP response containing a status code such as `200 OK`, headers and the HTML document. The browser parses the HTML into the DOM tree, discovers extra resources such as CSS, JavaScript, images and fonts and downloads them in parallel, builds the CSSOM from the CSS, combines the DOM and CSSOM into a render tree, calculates the layout (size and position of every box), paints the pixels and composites the layers onto the screen, while JavaScript may run and keep updating the page — and only then do I see the finished web page.

**Key terms:** URL · DNS · IP address · TCP · TLS/HTTPS · HTTP request/response · DOM · CSSOM · render tree · layout · paint
